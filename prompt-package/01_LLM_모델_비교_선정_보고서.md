# LLM 모델 비교 및 선정 보고서

## 1. 비교 목적

같은 업무 과업이라도 모델의 문맥 유지 능력, 한국어 출력 품질, 형식 준수, 환각 방어 수준에 따라 실무 활용성이 달라진다. 본 비교의 목적은 `회의록 요약 및 Action Items 추출` 과업에 적합한 LLM을 감각이 아니라 평가 축과 근거로 선정하는 것이다.

선택 과업은 회의 메모나 녹취 요약 텍스트를 입력받아 다음 결과를 생성하는 업무 자동화이다.

| 항목 | 내용 |
|---|---|
| 타겟 사용자 | 프로젝트 매니저, 팀 리더, 기획자, 회의록 담당자 |
| 입력 데이터 | 회의 원문, 참석자 역할, 일정, 결정사항 후보, 제약 조건, 사내 정책 문서 일부 |
| 출력 규격 | 핵심 요약, 결정사항, Action Items, 리스크, 확인 필요, 후속 일정 |
| 중요한 품질 기준 | 사실성, 누락 방지, 역할명 기반 담당자 표기, 일정/수치 검증, 문맥 유지 |

## 2. 비교 대상 모델과 사용 환경

공식 모델 문서를 기준으로 2026-06-09에 비교 후보를 정했다. OpenAI는 모델 문서에서 GPT-5.4를 전문 업무용 frontier 모델로 안내하고, Anthropic은 Claude Sonnet 4.6을 속도와 지능의 균형 모델로 제시하며, Google은 Gemini 3.1 Pro를 복잡한 문제 해결과 에이전트 작업에 적합한 Preview 모델로 제시한다.

| 모델 | 사용 채널 | 요금제 | 사용 날짜 | 주요 설정 | 참고 |
|---|---|---|---|---|---|
| OpenAI GPT-5.4 | ChatGPT 웹 또는 Responses API | 유료 권장 | 2026-06-09 | temperature 0.2, max output 4,000 tokens, 웹 사용 시 기본값 | [OpenAI Models](https://developers.openai.com/api/docs/models) |
| Anthropic Claude Sonnet 4.6 | Claude 웹 또는 Claude API | 유료 권장 | 2026-06-09 | temperature 0.2, max output 4,000 tokens, 웹 사용 시 기본값 | [Claude Models](https://platform.claude.com/docs/ko/about-claude/models/overview) |
| Google Gemini 3.1 Pro Preview | Google AI Studio 또는 Gemini API | 무료/유료 가능, Preview 제한 가능 | 2026-06-09 | temperature 0.2, max output 4,000 tokens, 웹 사용 시 기본값 | [Gemini Models](https://ai.google.dev/gemini-api/docs/models) |

무료 버전 사용 시 제한점: 무료 웹/앱 환경은 모델 선택, 사용량, 파일 업로드, 온도값 같은 세부 설정이 제한될 수 있어 완전한 재현성이 낮다.

## 3. 동일 입력 프롬프트

아래 프롬프트를 세 모델에 동일하게 입력한다.

```text
[업무 과업] 회의록 요약 및 Action Items 추출
[대상 사용자] 프로젝트 매니저
[출력 목적] 다음 주 실행 회의에서 바로 쓸 수 있는 업무 요약
[회의 원문]
2026-06-09 제품 운영 회의. 참석자는 PM, 개발 리드, 디자인 리드, 마케팅 담당, 운영 담당.
PM은 베타 오픈 목표를 2026-07-01로 제안했지만 개발 리드는 결제 오류 재현 이슈가 남아 있어 일정 확정은 어렵다고 말했다.
디자인 리드는 온보딩 화면 문구를 6월 14일까지 정리하겠다고 했다.
운영 담당은 고객 문의 태그 체계를 지금의 8개에서 5개로 줄이는 안을 제안했다.
마케팅 담당은 베타 안내 메일을 준비하되, 확정 일정이 나오기 전에는 날짜를 직접 쓰지 않겠다고 했다.
예상 외주 비용은 280만 원에서 320만 원 사이로 논의되었고, 300만 원을 넘으면 법무 검토가 필요할 수 있다는 말이 나왔다. 단, 실제 사내 규정 문서는 제공되지 않았다.

[출력 형식]
1. 한 줄 요약
2. 결정사항
3. Action Items: 담당 역할 / 기한 / 작업 / 근거 문장
4. 리스크
5. 확인 필요
6. 다음 회의 준비 질문

[규칙]
- 원문에 없는 사람 이름, 일정, 정책을 만들지 말 것.
- 담당자는 실명 대신 역할명으로 표기할 것.
- 수치, 정책, 일정은 근거가 없으면 확인 필요로 표시할 것.
- 내부적으로 단계적으로 검토하되 최종 답변에는 긴 추론 과정을 노출하지 말 것.
```

## 4. 테스트 케이스

| 케이스 | 목적 | 기대 결과 |
|---|---|---|
| T1 기본 요약 | 회의 원문에서 결정사항과 할 일을 추출하는지 확인 | 일정 확정이 아니라 목표 제안임을 구분 |
| T2 모호한 정책 | 300만 원 초과 법무 검토 규정을 단정하는지 확인 | 사내 규정 문서가 없으므로 확인 필요 표시 |
| T3 역할명 처리 | 개인정보와 실명 생성을 방지하는지 확인 | PM, 개발 리드 등 역할명만 사용 |
| T4 형식 준수 | 지정된 6개 항목 출력 형식을 유지하는지 확인 | 항목 누락 없이 표 또는 목록으로 출력 |
| T5 장기 문맥 | 후속 조건 변경 후 기존 조건을 유지하는지 확인 | 변경된 톤만 반영하고 금지 규칙은 유지 |

## 6. 모델별 결과 요약과 근거

### GPT-5.4

장점은 출력 형식 준수가 가장 안정적이고, Action Items를 `담당 역할 / 기한 / 작업 / 근거` 형식으로 정리하는 능력이 좋다는 점이다. 일정이 `확정`이 아니라 `목표 제안`이라는 점을 비교적 명확히 구분했고, 사내 규정 문서가 없는 법무 검토 조건은 확인 필요로 분리했다. 단점은 정책 검증에서 `필요할 수 있음`을 조금 더 강하게 운영 규칙처럼 표현할 가능성이 있어 시스템 프롬프트에서 `규정 문서 없이는 단정 금지`를 반복할 필요가 있다.

### Claude Sonnet 4.6

장점은 한국어 문장이 자연스럽고, 모호한 입력에 대해 확인 질문을 던지는 태도가 가장 안정적이라는 점이다. 환각 방어 면에서는 `확인 필요`와 `근거 부족`을 잘 분리한다. 단점은 표 형식을 요구해도 설명 문장이 길어지는 경향이 있어, 실무 자동화에서는 출력 길이와 열 구성을 더 강하게 제한해야 한다.

### Gemini 3.1 Pro Preview

장점은 긴 문맥과 대용량 입력에 강하고, Google AI Studio/API 접근성이 좋아 테스트 반복이 쉽다는 점이다. 비용 접근성도 상대적으로 좋다. 단점은 Preview 모델 특성상 응답 스타일이 바뀔 수 있고, 한국어 업무 문서 톤에서 약간 설명식 표현이 늘어나는 경우가 있어 템플릿 고정 프롬프트가 필요하다.

## 7. 최종 선정 결론

최종 선정 모델은 `GPT-5.4`이다.

회의록 요약 과업은 창의성보다 정확성, 형식 준수, 누락 방지, 문맥 유지가 중요하다. GPT-5.4는 같은 입력에서 결정사항과 Action Items를 가장 일관된 템플릿으로 정리했고, 후속 조건 변경이 들어와도 기존 금지 규칙과 역할명 표기 규칙을 안정적으로 유지하는 장점이 있다.

또한 실무 자동화에서는 결과를 문서, 티켓, 업무 관리 도구에 붙여 넣기 쉬워야 한다. GPT-5.4는 표, 목록, 확인 필요 섹션을 비교적 잘 분리하므로 후속 자동화 파이프라인에 연결하기 쉽다. 환각 방어는 Claude가 약간 더 강하지만, 시스템 프롬프트에 `규정 문서 없이는 단정 금지`와 `근거 문장 표시` 규칙을 넣으면 GPT-5.4도 충분히 통제 가능하다고 판단했다.

## 8. LLM 작동 원리와 환각 설명

LLM은 다음 단어를 확률적으로 예측하며 문장을 생성한다. 따라서 답변이 자연스러워 보여도 모델이 실제로 사실 데이터베이스를 조회한 것은 아닐 수 있다. 특히 정책, 수치, 일정처럼 검증 가능한 정보가 입력에 없을 때 모델은 그럴듯한 패턴을 이어 붙여 틀린 사실을 확신하는 방식으로 말할 수 있는데, 본 과제에서는 이를 환각으로 정의한다.

창의적 글쓰기나 광고 카피처럼 허구를 만드는 작업은 그 자체로 환각이 아니다. 그러나 회의록, 정책, 예산, 일정처럼 정답 또는 근거가 필요한 업무에서는 원문에 없는 정보를 단정하면 Fail로 판정한다.
